Регистрация использует логин и OPAQUE-пароль. Обязательные шаги Telegram → passkey/PRF → TOTP закрывают доступ к файлам до завершения настройки. Проверены возврат во вкладку после подтверждения Telegram, продолжение настройки после перезагрузки и изоляция второй сессии, прошедшей только пароль: завершение настройки в другой сессии не повышает её права.

Также проверены точное восстановление загруженных байтов, зашифрованные имена, локальное превью, новый изолированный браузерный контекст, смена пароля, вход и восстановление через passkey, отказ при повреждённом ciphertext, обязательный TOTP для парольного входа, разрушительный сброс через привязанный Telegram и новый пустой vault с новым паролем/passkey/TOTP. Подписанный BS=0 оставляет чтение, закрывает upload и показывает объяснение; повторная assertion с BS=1 возвращает upload. В захваченных запросах нет открытого пароля, имени или содержимого тестового файла. Email-форм нет.

Итоговый [release-manifest.json](../release-manifest.json) создан из тех же байтов `web/`, которые прошли полный браузерный прогон и проверку HTTP/HAR. Хеши текущих файлов дополнительно сверены с итоговым отчётом. `unit-checks.json` содержит полный подтверждённый прогон координатора в рабочем проекте Nimbus: системные проверки Django, отсутствие новых миграций, 144 backend-теста, 20 клиентских и 38 verifier/vendor-тестов. Это интеграционный охват обоих проектов, а не только отдельного клиента.

## Воспроизведение

В [cloud-nimbus-e2ee](https://github.com/wywywywycloud/cloud-nimbus-e2ee), клонированном с `--recurse-submodules`:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip install --no-deps -e .
# Node.js 24 и pnpm 11.19.0 должны быть в PATH.
(cd cloud-cypher && pnpm install --frozen-lockfile --ignore-scripts && pnpm exec playwright install chromium)
.venv/bin/python scripts/run_checks.py --report-dir new-reports
PLAYWRIGHT_MODULE="$PWD/cloud-cypher/node_modules/playwright" .venv/bin/python scripts/test_e2ee.py --report-dir new-reports
```

Стенд создаёт отдельные временные SQLite, storage, OPAQUE setup и браузерный профиль. Test-only `scripts/test_telegram.py` подменяет отправку сообщений бота и вызывает настоящий обработчик synthetic start/contact; настоящие сообщения не отправляются. Capture Telegram и все временные данные удаляются после проверки. Для Linux установите зависимости браузера через `pnpm exec playwright install --with-deps chromium`. Для установленного Chrome укажите `PLAYWRIGHT_CHANNEL=chrome`; `OPAQUE_NODE` задаёт путь Node. `--delivery-only` проверяет только поставку публичных ресурсов и контролируемую подмену.

## Проверенные границы

WebAuthn использует виртуальный CTAP2.1-аутентификатор Chrome с настоящими подписями и PRF. Физическая синхронизация Apple/Google/других менеджеров, восстановление их аккаунтов и реальная доставка Telegram не проверены. BE/BS — утверждения аутентификатора, а не независимая гарантия будущего восстановления у провайдера.

[Vendor integrity](vendor-integrity.json) — сохранённая ранее выполненная проверка закреплённого npm-архива OPAQUE 1.1.0. Локальные файлы по-прежнему совпадают с указанными хешами; скачивание архива в текущем прогоне не повторялось. Эта проверка воспроизводит опубликованные npm-байты, а не сборку Rust/WASM из исходников.

Проверка поставки относится к наблюдённым байтам и заголовкам: не блокирует исполнение подменённого кода, не удостоверяет происхождение произвольного HAR и не доказывает одинаковую выдачу всем посетителям. Отсутствие открытого тестового маркера само по себе не доказывает криптостойкость. Production-развёртывание, PostgreSQL-конкурентность, нагрузка и независимый аудит в этот отчёт не входят.
